# 从体验落差追到争议与责任

参考：APPSO《Claude 偷砍额度被抓包！AI 会员正在集体变成「鬼秤」》。依据用户提供的 PDF 及本次讨论提炼。学习的是材料组织与表达，不接受标题中的结论作为事实，文中产品、价格、测试与经营数据须重新核实。

## 何时使用

用户在付费、功能、额度、性能或规则变化中出现可描述的体验落差，且能取得投诉、测试、公告或回应等材料。入口是读者的具体利益，不必是金钱，也不预设一定存在欺骗。

## 可选展开

具体落差 → 可核对材料 → 相关主体回应 → 有依据的原因分析 → 本文能够支持的认识或未决问题。顺序可调，官方回应可前置；没有独立测试就不虚构，没有原因证据就保留未知，不固定写成揭黑报道或商业模式分析。

投诉用于呈现感受及线索，测试交代方法和适用范围，回应明确其主体与时点。材料有矛盾时说明矛盾，不为了叙事张力隐藏反证；未定论可在标题保留问题或归属，标题确定程度不能高于证据。

## 表达与配图

把术语、计量或规则转成使用者能感知的成本和处境。讽刺和比喻可强化认识，但不凭它推断厂商动机或认定责任。用户帖、进度条、数据图和官方回复各有用途，避免反复堆同类抱怨形成“截图多所以属实”的错觉。

事实材料呈现原始说法，图表解释差异，漫画可以收束感受；共同服务争议的核心问题，无须强求画风一致。截图与生成图遵循[配图参考](images.md)，漫画不能作指控依据。

涉及数据时检查单位、统计周期、样本、比较条件与分母；API 标价等值、实际支出、收入、成本和利润分别表述，估算写明假设，不能由吞吐和标价直接断言实际收入或毛利。

结尾回到已展开的关系，例如规则透明、知情或承诺兑现；是否落在这些问题上由材料决定，不要求所有体验争议都导向信任危机。
